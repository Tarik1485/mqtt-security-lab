MQTT Security Lab

Мета роботи

Дослідити захист MQTT-брокера за допомогою автентифікації користувачів, заборони анонімного доступу та TLS-шифрування з'єднання.

Інструменти

Eclipse Mosquitto 2.1.2

Mosquitto command-line clients

OpenSSL 3.6.5

Windows PowerShell

1. Налаштування брокера

Брокер Mosquitto працював локально на комп'ютері.

1884 — MQTT з автентифікацією за логіном і паролем.

8883 — MQTT через TLS з автентифікацією.

127.0.0.1 — обмеження доступу локальним комп'ютером.

allow_anonymous false — заборона анонімних підключень.

Приклад конфігурації міститься у файлі config/mosquitto.conf.example.

2. Автентифікація користувачів

Для тестування було створено користувачів admin, sensor та actuator.

Перевірено підключення адміністратора та публікацію повідомлення користувачем sensor.

Приклад тестового повідомлення:

Topic: test/sensor

Payload: temperature=25

Результат: брокер прийняв авторизоване підключення та повідомлення.

3. Перевірка заборони анонімного доступу

Виконано спробу публікації без логіна та пароля.

Результат: CONNACK (5), Connection Refused: not authorised.

Висновок: брокер відхиляє анонімні підключення.

4. Налаштування TLS

За допомогою OpenSSL створено центр сертифікації (CA), сертифікат CA, приватний ключ сервера та сертифікат сервера.

Сертифікат сервера містить імена localhost та IP-адресу 127.0.0.1.

TLS-слухач використовує порт 8883.

5. Перевірка захищеного з'єднання

Клієнт sensor успішно підключився до порту 8883, перевірив сертифікат за допомогою CA та відправив повідомлення temperature=26.

Адміністратор отримав повідомлення у темі test/secure:

test/secure temperature=27

Результат: успішна автентифікація та обмін повідомленнями через TLS підтверджені.

Спроба підключення без параметра --cafile завершилася помилкою перевірки сертифіката. Це підтверджує, що клієнт не довіряв сертифікату без явного надання CA; сама ця помилка не є окремим доказом блокування незашифрованого MQTT.

Висновок

Під час роботи налаштовано локальний MQTT-брокер Mosquitto, перевірено автентифікацію користувачів та заборону анонімного доступу. Створено сертифікати й перевірено успішне передавання повідомлень через TLS. TLS захищає дані під час передавання, а автентифікація обмежує доступ до брокера.

Безпека

Приватні ключі ca.key і server.key, файл паролів та справжні паролі не додаються до репозиторію. Брокер налаштований на локальний інтерфейс 127.0.0.1.
